# Operação da Release v1.12.0 — Guia de Implantação e Infraestrutura

## 1. Identificação da Versão

- **Versão:** `1.12.0` (`v1.12.0`)
- **Data de corte:** 2026-11-09
- **Escopo:** TimeBot AI com espectro vocal Web Audio API, persistência de conversas no PostgreSQL (migração 0035), calendário corporativo inteligente de feriados (migração 0034), busca/filtros/histórico de aprovações e relatórios M2M.

## 2. Migrações de Banco de Dados (PostgreSQL)

Esta entrega introduz duas migrações sequenciais:

1. **`0034_company_holiday.sql`**:
   - Cria a tabela `company_holiday` com índices em `date` (único) e `(is_active, date)`.
   - Gerencia feriados nacionais (BrasilAPI), regras de Vila Velha / ES e pontes/emendas manuais.
2. **`0035_timebot_threads.sql`**:
   - Cria a tabela `timebot_thread` com chave estrangeira em `public.user(id)` (`ON DELETE CASCADE`).
   - Índice composto `timebot_thread_user_updated_idx` em `(user_id, updated_at)`.
   - Armazena conversas JSON e chaves executadas (`executed_keys`) para evitar replay cross-device.

### Comando de Execução:
```bash
pnpm db:migrate
```

## 3. Variáveis de Ambiente e Provedores de IA

Nenhuma nova variável de ambiente é estritamente obrigatória para o funcionamento da v1.12.0. As integrações aproveitam as variáveis já existentes:
- `AZURE_AI_FOUNDRY_ENDPOINT` / `AZURE_AI_FOUNDRY_API_KEY`: Utilizadas prioritariamente pelo runtime de IA com isolamento de credenciais e circuit breaker automático.
- `DATABASE_URL`: Conexão do pool PostgreSQL (Azure Database for PostgreSQL).

## 4. Estratégia de Migração de Dados do Cliente

- **Cache Local & Write-Through:** As conversas do TimeBot continuam funcionando com hidratação imediata (0ms) a partir do `localStorage`.
- **Migração Transparente:** Na primeira montagem do componente [`useTimeBot`](file:///c:/Users/mgalv/Projetos-Programacao/Projetos-Treino/harvest/src/hooks/use-timebot.ts), qualquer conversa pré-existente no dispositivo local que não esteja no banco de dados é enviada via `PUT /api/ai/threads` sem ação manual do usuário.

## 5. Procedimento de Rollback

Em caso de necessidade de rollback da aplicação:
- As tabelas `timebot_thread` e `company_holiday` são retrocompatíveis e não quebram versões anteriores.
- O código da v1.11.0 ignora essas tabelas sem falhas operacionais.
